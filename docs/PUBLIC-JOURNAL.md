# 訪問者向け公開ページ

- `/`：管理者は管理画面、匿名・管理者以外は公開ページ。
- `/journal`：管理者も訪問者も同じ公開一覧を閲覧。
- `/admin`：管理者専用。匿名はログイン案内、それ以外はアクセス不可案内。
- `/api/state`：全分岐で管理者を検査。匿名401、それ以外403。DB操作より前に拒否。
- `/api/journal`：匿名で取得可能。公開用に限定したフィールドだけを返す。no-store。

管理者はSites所有者のプラットフォーム認証メールと、Sitesの秘密設定 `ADMIN_EMAIL` を照合する。ブラウザが送ったフォームのメールやowner指定は利用しない。本人データの保存キーには従来通りサイト内の安定したuserIdを使う。設定欠落時は全員を管理者として拒否する。ローカル検証だけ `.dev.vars` の架空のモックメールを利用する。秘密設定やローカルDBはGit管理しない。

## 掲載方法

1. 管理画面の「活動の記録」で記録を編集する。自由記録は「余暇のできごとを記録する」から追加する。
2. 共有範囲を「専用の要約のみ」または「全文」にする。
3. 表示予定の内容を確認し「公開ページに掲載する」を選んで保存する。
4. 「公開ページを見る」で確認する。掲載を外して保存すれば一覧から消える。

既存のshare_modeだけで公開しない。新しい `account.published_ids` の明示選択が必要。実行中、none、空のsummaryは掲載しない。JSON取り込みでは掲載指定を解除するため、復元だけで過去の記録が公開されない。

## 内容の制限と一括更新

`publicPost()` はid・title・body・date・kindだけを生成する。summaryは専用要約と一般見出しだけで、元のタイトル、活動日、メモ、関連種別を公開しない。fullでも非共有／削除済みタスク由来のタイトルは一般見出しにする。snapshot、感想、目標、非公開の関連情報は公開テーブルに格納しない。

`public_entries` は公開用の派生テーブル。業務更新と同じD1 batch・CAS条件で作り直す。記録の削除、共有範囲をnoneへ変更、全削除、JSON取り込みによる解除も同時確定する。公開APIはこのテーブルだけを読み、本人用テーブルを匿名へ渡さない。

候補から始めた記録は「試したこと」、自由記録は「余暇のできごと」、要約のみは「ひとこと」に分類する。終了済みとして記録された体験を表示するもので、抽選用triedフラグを公開履歴から再計算しない。

## 検証

`tests/publication.test.ts`：公開の明示選択、許可フィールド、非共有関連の見出し抑制、要約の本文分離、実行中／非共有の除外、管理者判定のfail-closedを検証。

`tests/publication-api.py`：ローカルD1で、匿名閲覧・初期未掲載・明示掲載・noneへの変更・summary・削除反映・管理APIの匿名拒否を検証。架空の試験記録を作成し削除する。本番データには触れない。

`tests/visitor-roles.py`：127.0.0.1:8787の本番WorkerでSitesの認証済みヘッダーを模擬し、管理者200／別ユーザー403／匿名401、公開ルート200を確認。ローカル基盤の再起動を示す特定の503だけを再試行する。本番のSites認証境界そのものの別アカウント試験とは区別する。

手動確認：PCと360px幅で公開一覧・種類別絞り込み、管理画面の共有設定→プレビュー→掲載保存を確認。19件の自動テストと型検査が合格。
